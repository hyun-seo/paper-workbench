# Paper Workbench

논문 PDF를 폴더에 넣으면 원본과 번역본을 나란히 보면서 노트를 남기고 질문할 수 있는 개인용 로컬 앱.

## 실행

```bash
cp .env.example .env   # 필요한 값만 수정
uv run uvicorn paper_workbench.main:app --host 0.0.0.0 --port 8000
```

브라우저에서 http://127.0.0.1:8000 을 연다.

번역은 기본으로 Claude Code CLI(`claude`)를 쓴다. 서버를 띄우는 계정에 CLI가 설치·로그인되어 있어야 한다.

## 사용

- **추가**: `inputs/` 폴더에 PDF를 넣으면 몇 초 안에 서재에 나타나고 번역이 시작된다.
  서재 화면에서 arXiv 링크나 PDF 직링크를 넣어도 된다 (받은 PDF는 `inputs/`에 저장된다).
- **읽기**: 왼쪽은 원본 PDF, 오른쪽은 문단 단위 번역.
  - 번역 문단을 누르면 원본의 해당 위치가, 원문을 누르면 그 문단의 번역이 하이라이트된다.
  - 번역문은 문장마다 줄을 바꿔 보여 준다. 문장 속 수식은 LaTeX로 렌더링된다.
  - 별행 수식·그림·표는 번역하지 않고 원본 영역을 잘라 그 자리에 이미지로 보여 준다.
- **요약**: 논문이 추가되면 한 줄 요약, 문제·방법·결과·한계, 주요 개념 5~10개를 자동으로 뽑는다.
  리더의 `노트 · 질문` 패널 `요약` 탭에서 보고, 개념을 누르면 그 개념이 설명된 쪽으로 이동한다.
- **종합**: 서재 상단 `종합`은 논문 요약들을 한데 읽어 서재 전체를 꿰어 보여 준다. 논문이 2편 이상이면 자동으로 만들고,
  논문이 추가·삭제되면 다시 만든다.
  - 전체 개관, 주제 묶음(논문마다 그 주제에서의 역할), 나란히 비교표, 논문 사이의 관계, 열린 질문과 아이디어, 읽는 순서.
  - 글 속의 〈논문 제목〉을 누르면 그 논문이 열린다.
  - **서재 전체에 질문**: 여러 논문에 걸친 질문을 한다. 논문 전문이 아니라 요약 카드와 종합을 바탕으로 답하므로,
    세부 수치나 증명은 해당 논문의 `질문` 탭에서 묻는다.
  - 종합 과정에서 같은 개념의 다른 이름을 하나로 합치고 약어(CLIP, ISP 등)를 별칭으로 저장한다.
- **지도**: 서재 상단 `지도`는 논문(네모, 색은 가장 잘 맞는 주제)과 개념(회색 동그라미)의 연결을 그린다.
  굵은 선은 종합에서 나온 논문 사이의 관계다. 점이나 굵은 선을 누르면 설명이 옆에 나오고, 범례의 주제를 누르면
  그 주제의 논문만 강조된다. `개념 보기`를 끄면 논문 사이의 관계만 남는다. 끌어서 옮기고 휠로 확대·축소한다.
- **개념**: 서재 상단 `개념`에서 모든 논문의 개념을 한데 모아 본다. 여러 논문에 걸친 개념이 위에 오고,
  논문 제목을 누르면 그 논문의 해당 쪽이 열린다. 다른 논문의 개념(또는 그 약어)이 본문에 3번 이상 나오면 `언급`으로 자동 연결된다.
- **전체 정리**: 서재 상단 `전체 정리 내려받기 (.md)`는 종합, 논문별 요약·개념·노트, 개념 색인을 Markdown 한 파일로 만든다.
  내려받을 때마다 현재 상태로 새로 생성된다.
- **노트**: 우측 상단 `노트 · 질문` 버튼의 `노트` 탭. 논문마다 하나, 자동 저장.
- **질문**: 같은 패널의 `질문` 탭. 논문 전문을 바탕으로 답하며 대화 기록은 논문별로 저장된다.
  - 원문이나 번역문을 드래그하면 뜨는 `이 부분 질문하기`로 그 구절(과 해당 원문 문단)을 붙여 질문한다.
  - 상단 `영역 선택`을 누르고 원본 PDF에서 수식·그림을 드래그하면 그 영역이 이미지로 첨부된다.
  - 구절과 이미지는 여러 개를 함께 붙일 수 있다. 질문 없이 보내면 "이 부분을 설명해 주세요"로 전송된다.
- **내보내기**: 상단 `내보내기`로 노트와 질문·답변 기록을 Markdown 파일로 저장한다. 첨부 이미지는 포함되지 않는다.
- **다시 추출**: 서재의 `다시 추출`은 PDF에서 문단·수식·그림을 다시 뽑는다. 원문이 그대로인 문단의 번역은 유지되고
  달라진 문단만 다시 번역한다. 추출 규칙이 바뀐 버전으로 올리면 서버가 뜰 때 기존 논문에 자동으로 적용된다.
- **삭제**: 서재에서 삭제하면 `inputs/`의 PDF는 `inputs/_removed/`로 옮겨진다.

## 설정 (`.env`)

| 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `TRANSLATOR` | `claude` | 번역·요약·종합·서재 질문 엔진. `claude` (Claude Code CLI) · `codex` (Codex CLI) · `openai` (API) |
| `CLAUDE_MODEL` | `sonnet` | `claude` 엔진의 모델. 빈 값이면 CLI 기본 모델 |
| `CODEX_MODEL` | (빈 값) | `codex` 엔진의 모델. 빈 값이면 CLI 기본 모델 |
| `OPENAI_API_KEY` | | 논문별 질문 기능과 `TRANSLATOR=openai`에 필요 |
| `OPENAI_MODEL` | `gpt-5-nano` | 논문별 질문 모델 (영역 선택 질문은 이미지 입력 지원 모델 필요) |
| `OPENAI_REASONING_EFFORT` | `low` | 추론 모델 속도 조절. 추론 모델이 아니면 빈 값으로 둔다 |
| `TARGET_LANG` | `한국어` | 번역 대상 언어 |
| `PAPERS_DIR` | `inputs/` | PDF를 넣어 두는 폴더 |
| `DATA_DIR` | `data/` | DB와 PDF 사본을 두는 폴더 |

엔진을 바꾸려면 `TRANSLATOR` 값만 바꾸고 서버를 다시 띄운다. 이미 번역된 문단은 그대로 남는다.

## 구조

```
paper_workbench/
  main.py        FastAPI 라우트, 논문 폴더 감시
  library.py     PDF 가져오기·중복 확인·다시 처리
  extract.py     PyMuPDF로 문단·수식·그림 블록과 좌표 추출
  translate.py   배치 번역 (Claude CLI / Codex CLI / OpenAI, 백그라운드, 재시작 시 이어서 진행)
  cards.py       논문별 요약 카드·개념 추출, 개념 색인, 전체 정리 Markdown
  synthesis.py   서재 전체 종합 (주제·관계·비교표·아이디어), 개념 이름 정리, 서재 전체 질문
  ask.py         논문 전문 + 선택 구절·이미지로 질문 답변 (OpenAI)
  db.py          SQLite 스키마
  static/        프런트엔드 (빌드 없음, PDF.js·KaTeX·d3는 CDN)
inputs/          여기에 PDF를 넣는다 (git 제외)
data/            SQLite DB와 PDF 사본 (git 제외)
```

## 알려진 한계

- 스캔본(이미지) PDF는 텍스트 추출이 안 된다.
- References 제목 이후의 문단은 번역하지 않는다. 그 뒤에 부록이 있으면 부록도 번역되지 않는다.
- 수식·그림·표 감지는 글꼴, 식 번호, 캡션 위치에 기대는 휴리스틱이라, 논문에 따라 놓치거나 본문 일부를 이미지로 잡을 수 있다.
  식 번호가 없고 변수를 본문 글꼴로 조판한 별행 수식은 놓치기 쉽다.
- 문장 속 수식은 PDF에서 뭉개진 글자를 모델이 LaTeX로 복원한 것이라 원본과 다를 수 있다. 원본 PDF에서 확인한다.
- 단이나 쪽을 넘어 이어지는 문단은 하나로 합쳐 번역하고 원본에서는 이어진 영역을 모두 칠한다. 번역 패널에서는 문단이 시작된 쪽에 놓인다.
- PDF 링크가 아닌 일반 웹페이지(HTML 논문)는 지원하지 않는다.
- 요약과 개념은 본문 앞 10만 자까지만 읽고 만든다. 모델이 고른 것이라 빠지거나 논문마다 이름이 갈릴 수 있고,
  이름이 갈린 개념은 종합 단계에서 모델이 합치지만, 손으로 합치거나 가르는 기능은 아직 없다.
- `언급` 연결은 개념의 영어 이름과 별칭을 본문에서 글자 그대로 찾는 방식이라, 다른 표현으로 쓴 경우는 놓친다.
- 종합은 논문 전문이 아니라 요약 카드를 읽고 만든 것이다. 주제 묶음·관계·아이디어는 모델의 해석이므로 출발점으로 쓰고,
  근거는 원문에서 확인한다. 논문 구성이 바뀔 때마다 통째로 다시 만들어 주제 이름과 묶음이 달라질 수 있다.
- 질문 시 논문 본문은 앞에서부터 12만 자까지만 모델에 전달된다.
